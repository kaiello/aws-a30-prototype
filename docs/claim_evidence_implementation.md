## Implemented and wired

- `standard_manifest.extract_reference_records` shares the existing lexer and
  range resolver. It preserves complete occurrences, Unicode spans, suffixes,
  unsupported panel qualifiers, page qualifiers and standalone page candidates.
  Kind tokens are lowercase; a single resolved element has a canonical
  `requested_label`, while `raw` and qualifiers retain the full request. Lists,
  ranges and ambiguous groups retain their complete expression and member order.
- `StandardManifest.validated_assets` validates each explicitly declared asset
  and retains healthy later members. Existing `asset_paths` reuses that seam
  and preserves its atomic failure behavior. No filename/page inference or new
  editable inventory is introduced.
- `evidence_resolution.resolve_claim_evidence` separates reference resolution,
  evidence binding, asset availability and claim support. Explicit per-claim
  selectors prevent matching through an unrelated source elsewhere in a
  retrieved pool. Selected canonical identities and page qualifiers are checked;
  native entry/span/hash equality is validated against the privileged reviewed
  fact view when supplied. Ordinary generated claims lack that expected proof.
  Links expose selected/expected entry and span metadata with binding hashes;
  the proof projection omits source text.
- Selected context roles remain visible in `binding_evidence`. Explicit
  `relationship` values `navigation_candidate`/`ui_companion`, or
  `selection_role="ui_companion"`, cannot fill a required selected-source role.
  Ordinary all-navigation selection is unavailable; mixed or privileged
  selection is incomplete. These exact server encodings are supported; an
  undocumented `selection_role="candidate_navigation"` alone is not recognized.
  A literal exact citation can still have a direct reference role independently
  of its chosen context's navigation role.
- Only a server-derived `project_reviewed_facts` view can grant reviewed support.
  Exact complete fact IDs, ordering, qualifications and native bindings remain
  required. Caller flags, page overlap, graph links and available pixels grant
  no semantic authority. Empty known-required fact sets are insufficient.
- `query.async_query` attaches the additive links and assessment. Generated
  claims retain `UNASSESSED`; current generic extraction supplies no explicit
  selectors, so their binding usually remains unavailable. Extraction may miss
  prose claims. Failed reviewed bindings return source-free
  `EVIDENCE_BINDING_FAILED`/HTTP 503 without model fallback.
- The UI displays independent states, all ordered figure assets and image-only
  table evidence. Canonical claim assets cover compact references and healthy
  subsets omitted by legacy whole-set navigation. Request generations prevent
  late responses from replacing a newer query or figure inspection.

`declared_assets` preserves raw manifest declaration order. `assets` preserves
the existing source-anchor render order and contains only byte-validated
available members. Their many-to-many `source_anchor_orders` are retained;
arrays are never zipped to pages. Typed companions and ambiguous parent/group
images remain navigation candidates and cannot satisfy direct support.
