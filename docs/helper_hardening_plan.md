- **Citations:** `standard_manifest.py:357-394` already resolves complete case/dotted IDs, plural comma/“and” lists, inherited prefixes, first-seen deduplication and unresolved/group diagnostics. `resolve():241-255` and `source_anchors():271-276` own canonical labels/stable source IDs. - **Retrieval compatibility:** `pre_retrieval.py:161-173` deliberately tokenizes singular references before calling `extract_references(..., lists=False)`; `expand_query():193-238` uses those results in search text. Its wrapper can truncate Unicode ranges before the shared parser sees them. It must be guarded explicitly, rather than assuming a shared-parser change automatically preserves enrichment.
- **Terminology:** `extract_clause4_glossary()` emits page-level chunks and text cross-references (`extract.py:64-103`), not per-term alias records. `WELDING_ACRONYMS`/`expand_query()` are scalar acronym expansions, not a nonstandard-term mapping schema (`pre_retrieval.py:27-107,175-238`). `extract_see_also_terms()` is a UI link extractor, not a normative alias resolver (`query.py:75-102`). `build_dual_graph.py:227-247` keeps existing ontology IDs; `:251-281` classifies cached raw edges and uses `key=rel`. - **Actual contextual reader:** `contextual_indexer.py:129-137` currently summarizes possible headwords with a simple line split, not the uppercase-only regex the patch claims to replace. `:42-47,94-145` owns local BGE model loading, contextual records and FTS synchronization.
